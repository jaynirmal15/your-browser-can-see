The usual shape

Video goes up,
an answer comes back

  • Every frame crosses the network
  • You pay per call, forever
  • Round-trip latency you can feel
  • Someone else's server holds someone's face

Or it doesn't move at all

The model runs in the tab. The camera frame never leaves the machine it was captured on.

That isn't a privacy slogan. It's an architecture, and it has real limits — we'll get to those.

What a rep counter actually is

Not machine learning.
A threshold and a flag.

  • The model gives you coordinates, not meaning
  • Angle at the elbow from three points: shoulder, elbow, wrist
  • down when > 150°, up when < 55°
  • Count on the transition, not the state — otherwise you count frames

Every "AI feature" built on pose is this: a small amount of geometry sitting on top of a model that only ever reports where things are.

The runtime question

WebAssembly or WebGPU?

WASM + SIMD

  • Works essentially everywhere
  • CPU-bound — competes with your app
  • Predictable, unexciting, fine

WebGPU

  • Much faster when present
  • Still uneven across browsers and drivers
  • Falls back — so you need the fallback to be good

Pick the delegate at runtime, measure on the oldest machine you care about, and ship the fallback path as the one you actually tested.

The scheduling question

Don't run inference
on every frame

  • 60 fps of camera does not need 60 fps of model
  • Gate on video.currentTime — the same frame twice is wasted work
  • Faces move slowly. 10–15 Hz looks live to a human
  • Keep drawing at full rate; interpolate between results
  • Heavy work belongs off the main thread, or the page stops responding
Being honest about it

When a server is still
the right answer

  • Accuracy you can defend. Lite models are lite
  • Battery. Continuous inference is a real draw on a laptop and brutal on a phone
  • Consistency. You control one server; you do not control their GPU
  • Anything you must audit — you can't log what you never received
  • Models too large to ship. 20 MB is fine. 2 GB is not

On-device wins where the data is sensitive, the volume is high, and "good enough, instantly, free" beats "excellent, eventually, metered."

The pattern

Load a model once. Gate inference on new frames. Draw every frame.
Read coordinates, not meaning. Measure on the slow machine.
